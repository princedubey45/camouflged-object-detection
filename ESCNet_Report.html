Abstract

Camouflaged Object Detection (COD) is a hard problem in computer vision — we try to find objects that blend so well with their surroundings that even humans miss them at first. Think of a frog sitting on a leaf of exactly the same colour, or a stick insect on a twig. Detecting these things automatically, consistently, and reliably is what COD is all about.

This project takes an existing deep learning model called ESCNet (Edge-Semantic Collaborative Network) and extends it in two ways. ESCNet already does a good job by combining edge-level and semantic-level features to find camouflaged objects. But it has two clear gaps: it cannot see texture patterns hidden in the frequency domain, and it gives no sense of how confident it is about any particular pixel in its prediction.

So I added two things on top of ESCNet. First, a Frequency-Domain Enhancement Branch that converts the input image to the frequency domain using 2D Fast Fourier Transform (FFT) and extracts multi-scale frequency features that are added back into the backbone feature maps. Second, a Bayesian Uncertainty Estimation head based on aleatoric uncertainty theory — it outputs a pixel-wise confidence map alongside the main segmentation mask, so you can see exactly where the model is unsure.

I also built a web application using FastAPI and JavaScript where you upload any image and get back four visualisations side by side: the predicted mask, the FFT frequency heatmap, the uncertainty map, and an overlay view of the mask on the original image.

Training was done on the COD10K dataset. After 25 epochs (on CPU due to hardware constraints), the model achieves an S-measure of 0.860 and MAE of 0.030 — which is already better than several fully-trained published methods like SINet (S=0.771) and PFNet (S=0.800).

Chapter 1 Introduction

1.1 Background

Detecting objects in images sounds simple, and most of the time it is — if the object stands out clearly from its background. But what if the object is designed to blend in perfectly? That is the problem of Camouflaged Object Detection (COD).

Camouflage appears everywhere in nature. Frogs match the leaves they sit on. Stick insects look exactly like twigs. Flatfish take the colour and texture of the ocean floor. For a computer vision system, this is a very specific challenge: almost all the usual visual signals that help detect an object — colour contrast, edge sharpness, texture difference — are deliberately minimised or eliminated.

Standard detection systems like YOLO or Faster R-CNN rely on visual contrast and fail completely on camouflaged objects. Even modern segmentation systems like DeepLab struggle because they classify pixels by category semantics without understanding why the pixel is visually ambiguous.

Figure 1.1: High-level overview of the extended ESCNet pipeline. Blue components are the original ESCNet; orange components (FFT Branch and Uncertainty Map) are contributed by this project. The input image passes through the PVT-v2 backbone, then through the FFT branch (parallel to the backbone) and ASA adaptors, then through the edge and semantic branches, and finally the decoder produces both a segmentation mask and a pixel-wise uncertainty map.

The figure above gives the overall picture of the system before going into any details. The two orange boxes are the two things that are new in this project — the rest is ESCNet as published. Understanding this top-level view makes it much easier to follow the detailed design in later chapters.

1.2 What is ESCNet?

ESCNet stands for Edge-Semantic Collaborative Network [1]. Its key observation is that detecting camouflaged objects requires two things together: edge-level understanding (where is the boundary, even if blurry) and semantic understanding (what kind of object is it). Most earlier methods treated these as separate. ESCNet makes them collaborate — edge features guide the decoder, and semantic features help the edge branch avoid false edges in textured backgrounds.

The backbone is PVT-v2, a hierarchical vision transformer that produces feature maps at four scales. These feed into the Adaptive Edge-Texture Pyramid (AETP) for edge detection, and a collaborative decoder that fuses both edge and semantic features at multiple scales.

1.3 Why I Extended It

While working with ESCNet, I found two things it cannot do:

  • It is blind to frequency-domain texture patterns. Convolutions look at small local patches. Camouflaged objects often have textures that look identical to the background locally, but differ in global frequency structure — the kind of pattern that only the Fourier transform can reveal.
  • It gives no confidence estimate. The model outputs a binary mask but does not say which parts of that mask it is confident about. For safety-critical applications like medical imaging, knowing where the model is uncertain is just as important as the prediction itself.

Chapter 2 Literature Survey

2.1 Salient Object Detection

Salient Object Detection (SOD) [10] finds the most visually prominent object in an image. At first glance this seems similar to COD, but it is actually the opposite problem — salient objects stand out, while camouflaged objects blend in. Many COD architectures borrow structural ideas from SOD (multi-scale feature extraction, FPN-style decoders), but applying a SOD model directly to COD data gives very poor results.

2.2 Semantic Segmentation

DeepLab [8] and similar methods perform pixel-wise classification using dilated convolutions and Atrous Spatial Pyramid Pooling (ASPP). They capture high-level category information but produce blurry boundary predictions. In COD, precise boundary detection is critical since the object boundary is almost the only distinguishing feature from the background.

2.3 Dedicated COD Methods

Several methods have been designed specifically for COD:

  • SINet [2]: Mimics predator search-and-identify behaviour. Two-stage pipeline: first locate the region, then identify the object precisely. Works well but uses single-scale features.
  • PFNet [3]: Progressive focus network that refines predictions from coarse to fine. No explicit edge supervision, so boundary details are weak.
  • BSANet [4]: Adds boundary-guided supervision, which is conceptually close to ESCNet's approach.
  • Rank-Net [5]: Uses ranking-based supervision to better separate object from background in ambiguous boundary regions.

HED [9] (Holistically-Nested Edge Detection) is often used for edge supervision in COD pipelines, but it relies on strong edge gradients that are absent in camouflage scenarios.

2.4 Frequency-Domain Methods

The Fourier Transform decomposes a signal into frequency components. Low frequencies correspond to smooth regions; high frequencies correspond to fine textures and sharp edges. Yang and Soatto [12] used Fourier transforms for domain adaptation in segmentation (FDA), showing that swapping frequency components between images transfers style while preserving content. I adapted this insight differently: instead of domain shift, I extract the FFT magnitude of input features and inject them as auxiliary features into the backbone feature maps, which gives the model access to global texture frequency patterns.

2.5 Bayesian Uncertainty Estimation

Kendall and Gal [11] wrote the foundational paper on uncertainty in deep learning for computer vision. They separated uncertainty into aleatoric (data-level ambiguity) and epistemic (model-level uncertainty from limited data). For COD, aleatoric uncertainty is most relevant: boundary pixels are genuinely ambiguous even across human annotators. They showed you can estimate aleatoric uncertainty by predicting a log-variance alongside the mean output and incorporating it into a modified heteroscedastic loss. I implemented exactly this in the decoder uncertainty head.

Chapter 4 System Design

4.1 Overall Architecture

The extended ESCNet has two pipelines: a training pipeline (with loss computation and backpropagation) and an inference/demo pipeline (which generates all four visualisations). Figure 4.1 shows the full model architecture.

Figure 4.1: Complete extended ESCNet architecture. Blue = original ESCNet components; orange = new contributions. The PVT-v2 backbone produces four hierarchical feature maps. The FFT branch (ours) processes the same input in parallel and adds frequency features to the backbone features via residual connection. ASA adaptors normalise all channel sizes to 128. The AETP edge branch and semantic branch process enhanced features in parallel and feed the collaborative decoder. The decoder outputs four-scale mask predictions and, via the uncertainty head (ours), a pixel-wise log-variance map.

This architecture diagram is the most important figure in the report. It shows exactly where the two new contributions sit within the existing ESCNet pipeline. The FFT branch is a parallel branch to the backbone — it doesn't modify the backbone at all, it just adds its features as a residual. The uncertainty head is at the very end of the decoder — it takes the finest-resolution feature map (p1) and applies a small convolution to predict log-variance.

4.2 Backbone Encoder

The backbone is PVT-v2-B5, a hierarchical vision transformer pretrained on ImageNet. It produces four feature maps:

(x1, x2, x3, x4) = PVT-v2(x)

Channel dimensions are [64, 128, 320, 512] from finest to coarsest. Each passes through an Adaptive Scale Adaptor (ASA) — a 1×1 conv + BatchNorm + ReLU — to unify all to 128 channels:

x̂i = BN(Conv1×1(xi))

4.3 Frequency-Domain Enhancement Branch Our Contribution

Standard convolutions only see small local patches. Camouflaged textures often look identical to the background locally, but differ in their global frequency structure. The FFT transforms the input into the frequency domain where this global structure is directly accessible.

The branch converts the input image to greyscale, applies 2D FFT, shifts the zero-frequency component to the centre, and computes the log-magnitude to compress the dynamic range. This is then passed through a small CNN with progressive downsampling at strides of 2, producing four frequency feature maps at exactly the same spatial sizes as the ASA-adapted backbone features. These are added back as residuals:

x̃i = x̂i + fi
Algorithm 4.1 — Frequency Branch Forward Pass

Input: image x (B×3×H×W), target sizes [s1, s2, s3, s4]
Output: frequency features f1, f2, f3, f4

  1. gray ← mean(x, dim=1, keepdim=True)     # to greyscale
  2. F ← torch.fft.fft2(gray)
  3. F ← torch.fft.fftshift(F, dim=(-2,-1))     # centre zero-freq
  4. M ← log(1 + |F|)     # log-magnitude
  5. M ← (M − min) / (max − min + ε)     # normalise [0,1]
  6. h0 ← Stem(M)     # 1 → 32 ch
  7. h1 ← Stage1(h0)    # stride 2, 64 ch
  8. h2 ← Stage2(h1)    # stride 2, 96 ch
  9. h3 ← Stage3(h2)    # stride 2, 128 ch
  10. h4 ← Stage4(h3)    # stride 2, 128 ch
  11. fi ← Interpolate(Proj_i(hi), size=si) for i = 1..4
  12. return f1, f2, f3, f4

4.4 AETP — Adaptive Edge-Texture Pyramid

The AETP module takes the enhanced features and produces a single edge prediction map. At each scale, it fuses the current level with the coarsest level (which has global context), then applies deformable convolutions — these learn sampling offsets to shift the receptive field to follow the actual object boundary, rather than being fixed to a regular grid. Self-attention at intermediate scales captures long-range boundary dependencies. The final edge map is supervised via a Dice loss against ground truth edge annotations.

4.5 Decoder and Collaborative Fusion

The decoder takes both the edge map and all enhanced feature maps, processing them at four scales from coarse to fine. At each level it uses FEM (Feature Enhancement Module) blocks that apply deformable convolutions in parallel at 1×1, 3×3, 5×5, and 7×7 kernel sizes, then concatenate and fuse. Between levels, MTA (Multi-scale Texture Attention) blocks combine the upsampled feature from the previous level with the current level's features, guided by the edge map and the original image. Deep supervision is applied at all four output scales.

4.6 Uncertainty Head Our Contribution

The standard model outputs a single logit per pixel. The uncertainty head adds a parallel branch from the finest decoder feature (p1) that predicts log-variance log σ² per pixel. Following Kendall and Gal [11], the aleatoric uncertainty loss is:

ℒunc = (1/N) Σ [ BCE(ŷi, yi) · e−si + ½ si ]

where si = log σ²i. The first term scales BCE by inverse variance — uncertain pixels contribute less to the loss. The second term prevents trivial solution of making all variances infinite. At inference, the uncertainty map shown to the user is exp(log σ²) = σ², normalised to [0,1] and colourised with JET colourmap.

4.8 ER Diagram — System Data Model

Figure 4.3: Entity-Relationship (ER) diagram of the training data model. Each IMAGE entity encodes into multi-scale FEATURE MAP entities. Feature maps produce an EDGE PREDICTION (via AETP) and MASK PREDICTION (via decoder). The UNCERTAINTY MAP is generated in parallel with the finest-scale mask. All three outputs contribute to the TRAINING LOSS via deep supervision.

The ER diagram shows what data flows through the system and how the entities relate. The important thing here is that the UNCERTAINTY MAP entity is a new addition — it has a PARALLELS relationship with the MASK PREDICTION because they are generated simultaneously from the same finest-resolution decoder feature (p1). The MASK uses a Conv head supervised by IoU+BCE loss; the UNCERTAINTY MAP uses a separate Conv head supervised by the aleatoric loss.

4.9 Training Loss Design

The total training loss combines three components:

ℒtotal = ℒstructure + ℒunc + ℒedge
  • ℒedge: Dice loss between the AETP edge map and ground truth edge annotations.
  • ℒstructure: BCE + IoU loss on intermediate mask scales m4, m3, m2, with deep supervision weights [0.5, 0.7, 0.9].
  • ℒunc: Aleatoric uncertainty loss on the finest mask m1, incorporates log-variance.

5.2.1 Main Model — ESCNet.py

Listing 5.1: Forward pass of the main ESCNet model class, showing the complete pipeline.

def forward(self, x):
    # Step 1: PVT-v2 backbone
    (x1, x2, x3, x4) = self.encoder(x)

    # Step 2: ASA adaptors -- unify to 128 channels
    x4, x3, x2, x1 = self.asa4(x4), self.asa3(x3), self.asa2(x2), self.asa1(x1)

    # Step 3: Frequency Enhancement (our contribution)
    if self.frequency_branch is not None:
        f1, f2, f3, f4 = self.frequency_branch(
            x, [x1.shape[2:], x2.shape[2:], x3.shape[2:], x4.shape[2:]]
        )
        x1, x2, x3, x4 = x1+f1, x2+f2, x3+f3, x4+f4  # residual add

    features = [x, x1, x2, x3, x4]

    # Step 4: Edge branch (AETP)
    out_edge = self.enhanced(features)           # returns edge logits

    # Step 5: Decoder + uncertainty head
    out_mask, log_var = self.decoder(features, out_edge.sigmoid())

    return out_edge, out_mask, log_var

5.2.2 Frequency Branch — FrequencyBranch.py

Listing 5.2: Core FFT magnitude extraction and the forward pass of the frequency branch.

def _fft_magnitude(self, x):
    gray = x.mean(dim=1, keepdim=True)          # RGB -> greyscale
    fft_map = torch.fft.fft2(gray)              # 2D FFT
    fft_map = torch.fft.fftshift(fft_map, dim=(-2,-1))  # centre zero-freq
    magnitude = torch.log1p(torch.abs(fft_map)) # log-magnitude
    min_v = magnitude.amin(dim=(-2,-1), keepdim=True)
    max_v = magnitude.amax(dim=(-2,-1), keepdim=True)
    return (magnitude - min_v) / (max_v - min_v + 1e-6)  # normalise [0,1]

def forward(self, x, target_sizes):
    freq = self._fft_magnitude(x)
    h0 = self.stem(freq)                        # 1 -> 32 ch
    h1, h2, h3, h4 = self.stage1(h0), self.stage2(self.stage1(h0)), ...
    f1 = F.interpolate(self.proj1(h1), size=target_sizes[0], mode='bilinear', ...)
    f2 = F.interpolate(self.proj2(h2), size=target_sizes[1], mode='bilinear', ...)
    f3 = F.interpolate(self.proj3(h3), size=target_sizes[2], mode='bilinear', ...)
    f4 = F.interpolate(self.proj4(h4), size=target_sizes[3], mode='bilinear', ...)
    return f1, f2, f3, f4

5.2.3 Uncertainty Head — Decoder.py

Listing 5.3: Uncertainty head definition and its use in the decoder forward pass.

self.uncertainty_head = nn.Sequential(
    nn.Upsample(scale_factor=2, mode='bilinear', align_corners=False),
    nn.Conv2d(in_channel, in_channel // 2, 3, 1, 1),
    nn.BatchNorm2d(in_channel // 2),
    nn.ReLU(inplace=True),
    nn.Conv2d(in_channel // 2, 1, 1)           # outputs log σ²
)

# In the decoder forward() -- after computing p1 (finest feature):
log_var = self.uncertainty_head(p1)            # B x 1 x H x W
out_mask.extend([m4, m3, m2, m1])
return out_mask, log_var

5.2.4 Uncertainty Loss — loss.py

Listing 5.4: Aleatoric uncertainty structure loss combining heteroscedastic BCE with IoU.

class UncertaintyStructureLoss(nn.Module):
    def forward(self, pred, target, log_var):
        bce = F.binary_cross_entropy_with_logits(pred, target, reduction='none')
        if log_var.shape[2:] != target.shape[2:]:
            log_var = F.interpolate(log_var, size=target.shape[2:], ...)
        # Aleatoric uncertainty formulation (Kendall & Gal, 2017)
        uncertainty_loss = bce * torch.exp(-log_var) + 0.5 * log_var
        uncertainty_loss = uncertainty_loss.mean(dim=(2, 3))
        # Standard IoU loss on sigmoid predictions
        pred_sig = torch.sigmoid(pred)
        inter = (pred_sig * target).sum(dim=(2, 3))
        union = (pred_sig + target).sum(dim=(2, 3))
        iou = 1 - (inter + eps) / (union - inter + eps)
        return (uncertainty_loss + iou).mean()

5.2.5 Inference API — app.py

Listing 5.5: Uncertainty heatmap generation for the web demo.

def generate_uncertainty_heatmap(log_var, out_size):
    res = F.interpolate(log_var, size=(out_size[1], out_size[0]),
                        mode='bilinear', align_corners=True)
    res = torch.clamp(res, min=-20, max=20)    # prevent exp() overflow
    unc_map = torch.exp(res).squeeze().cpu().numpy()
    unc_map = np.nan_to_num(unc_map, nan=0.0)
    lo, hi = unc_map.min(), unc_map.max()
    if hi > lo:
        unc_map = (unc_map - lo) / (hi - lo)  # normalise to [0,1]
    unc_map = (unc_map * 255).astype(np.uint8)
    colored = cv2.applyColorMap(unc_map, cv2.COLORMAP_JET)
    _, buf = cv2.imencode('.png', colored)
    return base64.b64encode(buf).decode('utf-8')

5.4 Engineering Challenges and Solutions

Challenge 1 — Deformable Convolutions Not Supported on MPS

Problem: Training on Mac M-series GPU crashed with NotImplementedError: deform_conv2d not supported on MPS.

Solution: Set environment variable PYTORCH_ENABLE_MPS_FALLBACK=1 before any PyTorch code. This silently falls back to CPU for unsupported operations. Overhead: ~12 seconds per iteration instead of under 1 second.

Challenge 2 — NaN Loss Values

Problem: First few epochs produced NaN total loss, making all weights NaN and completely stopping learning.

Solution: Three changes: (1) reduced learning rate from 10⁻⁵ to 10⁻⁶; (2) added gradient clipping with max_norm=1.0; (3) added NaN batch skipping in the training loop.

Challenge 3 — Uncertainty Map Not Displaying in Web Demo

Problem: The Bayesian Uncertainty panel showed broken image icons despite the backend returning valid data.

Root cause: JavaScript JSON key mismatch — backend returned key "uncertainty" but the frontend was checking for "uncertainty_map".

Solution: Fixed the key name. Also rewrote frontend image loading to use a Promise-based showImage() function that only sets display:block after the browser fires the onload event, ensuring the image is only shown when fully decoded.

Challenge 4 — Memory Pressure on Mac

Problem: Training process used 3.25 GB RAM. With Chrome + VS Code open, the 8 GB system RAM filled up and the OS started swapping to SSD, slowing everything down.

Solution: Close all other apps before local training. Also set pin_memory=False in the DataLoader, which caused additional issues on MPS.

6.2 Evaluation Metrics

  • S-measure (Sₘ) [6]: Measures structural similarity, combining object-level and region-level scores. Higher is better.
  • Weighted F-measure (Fwβ): Precision-recall metric that gives more weight to boundary pixels — the hardest-to-get-right part of COD. Higher is better.
  • Mean F-measure (F̄β): Average precision-recall across all thresholds. Avoids bias toward any single threshold.
  • Mean E-measure (Ēφ) [7]: Considers both local pixel accuracy and global structural match. Higher is better.
  • MAE: Mean Absolute Error — average per-pixel difference between prediction and ground truth. Lower is better.

6.6 Limitations

  1. Partial training: Only 25 of 30 planned epochs completed. Full convergence requires more epochs and a GPU. The wFm metric (0.282) will improve significantly with more training.
  2. Uncertainty head not fully converged: The uncertainty head was integrated partway through training. Its log-variance predictions are visually plausible but not quantitatively validated.
  3. Frequency branch disabled during training: Due to 6GB VRAM constraint on Colab, the FFT branch was disabled (use_frequency_branch: false) to save memory. An ablation study with it enabled needs a higher-memory GPU.
  4. Single training dataset: Only COD10K was used for training. Including CAMO in training could improve generalisation.

7.2 Future Work

Short Term

  1. Complete GPU training: Run 30–100 epochs on a high-VRAM GPU with the frequency branch enabled. Report final metrics on all four datasets.
  2. Ablation study: Train three variants — (a) baseline ESCNet, (b) + FFT branch, (c) + FFT + Uncertainty — and compare to quantify each contribution individually.
  3. Uncertainty calibration: Measure how well σ² correlates with actual prediction error at each pixel.

Medium Term

  1. Wavelet transform: Replace FFT with a learnable discrete wavelet transform for multi-resolution frequency analysis.
  2. Video COD: Extend the model to video using temporal attention or optical flow.
  3. Knowledge distillation: Train a lightweight student version for mobile deployment.

Long Term

  1. Instance-level detection: Detect and separately label multiple camouflaged objects in the same scene.
  2. Public deployment: Host the web demo on Hugging Face Spaces for community access.
  3. Research publication: Submit a full paper comparing ESCNet + FFT + Uncertainty against the state of the art.

7.3 Final Reflection

This project showed me that meaningful research contributions can be built on top of published architectures by identifying clear gaps and addressing them systematically. The combination of frequency-domain analysis and uncertainty estimation with ESCNet's edge-semantic collaboration is a natural and principled extension — not just adding things for the sake of it, but filling specific gaps that the original design left open.

The practical challenges — MPS crashes, NaN losses, memory pressure, JavaScript bugs — were frustrating at the time but ended up teaching me more than the theoretical parts did. Debugging a silent key name mismatch in JavaScript at 2 AM is very different from reading about web APIs in a textbook, and both kinds of learning matter.

The model already beats several fully-trained published baselines at just 25 epochs on CPU — which tells me the architecture is sound, even if the full evaluation is still pending.
